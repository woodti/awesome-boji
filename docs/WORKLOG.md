## 2026-10-15 18:32：计算器脚本失效时的隐私保护

- 开始时工作区干净，main 与 origin/main 一致；上一轮 10f4617 的 Actions 已成功。本轮没有新增同义文章，也不重复提交搜索平台。
- 检索公开计算器的本地数据处理场景，结合源码发现：身体输入表单没有服务端用途，但默认 GET 提交依赖 JavaScript preventDefault 拦截。脚本禁用或加载失败时，原控件仍能输入并把参数拼进 URL。这是代码路径风险，不代表已经观测到真实用户数据泄露。
- 按 MDN 的 form、disabled、CSP form-action 官方文档核对行为。两个计算器默认禁用，在各自本地提交处理器注册后才启用；增加未就绪与无脚本提示，关闭表单自动补全。工具页单独声明 form-action 'none'，阻止原生表单网络提交，不改变训练计划的 GET 参数分享。
- 资料：https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/form 、https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/disabled 、https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/form-action 。未新增健康建议；计算仍不上传、不持久化。
- 真实 Chrome 使用虚构测试输入核对热量 1979 / 静息 1649、蛋白质 98–140；计算期间 Network.requestWillBeSent 为 0。分别禁用脚本及阻断工具脚本请求重载，两种情况的计算按钮均不可用、提示可见，之后恢复全部临时调试设置。
- 构建产物检查新增本地计算的隐私约束：工具页必须阻止原生提交，两个表单的控件必须处于默认禁用的 fieldset 内。界面保持原工具样式，新增提示只在未就绪时显示；无新增配图或排版方向。
- 格式、5 项核心测试、类型、构建、29 页站内检查通过；390 / 768 / 1440 宽度浏览器截图无横向溢出。上一轮新增文章上线后已通过 28 页正式站 SEO 检查；本轮发布继续以当前提交的 Actions 与线上验证为准。
